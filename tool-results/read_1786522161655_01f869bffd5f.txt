    36→    36→## 3. Visual Effects — Classification & Implementation Framework
    37→    37→
    38→    38→**DO NOT assume a fixed set of effects.** Every template is different. Use this classification system to **analyze the template, identify ALL effects, and implement each one correctly.**
    39→    39→
    40→    40→### 3.1 Effect Classification Taxonomy
    41→    41→
    42→    42→When reading a template, classify every visual effect into one or more of these categories:
    43→    43→
    44→    44→| Category | Description | Trigger | Rendering | Typical Examples |
    45→    45→|---|---|---|---|---|
    46→    46→| **A. Canvas Animation** | Continuous `<canvas>` animation running via `requestAnimationFrame` | Mount → unmount lifecycle | Canvas 2D context | Particle fields, ASCII spheres, wave patterns, dot grids, flowing lines, fractals, noise fields |
    47→    47→| **B. Scroll-Triggered Reveal** | Element transitions from hidden → visible on scroll into viewport | IntersectionObserver | CSS transitions (opacity, transform) | Fade-up, slide-in, scale-in, blur-in, clip-path reveal |
    48→    48→| **C. Scroll-Driven Transform** | Element transform changes continuously based on scroll position | Scroll event (passive) | Inline style or CSS variable | Parallax backgrounds, progress bars, sticky sections, scale-on-scroll |
    49→    49→| **D. CSS Keyframe Animation** | Pure CSS `@keyframes` animations, infinite or finite | CSS only (auto on mount) | CSS rendering | Pulse, blink, rotate, marquee, float, shake, gradient shift |
    50→    50→| **E. Hover / Focus Micro-interaction** | State change on user interaction | Mouse/focus event | CSS transition or JS | Glow, lift, color shift, border highlight, shadow expand |
    51→    51→| **F. Staggered Sequential Reveal** | Multiple child elements appear one-by-one with delays | Timer chain (React state or setTimeout) | CSS transitions | Terminal lines, feature lists, step indicators, card grids |
    52→    52→| **G. Background Atmosphere** | Decorative layered backgrounds, non-interactive | Static or CSS animated | CSS (gradients, pseudo-elements, SVG filters) | Noise texture, radial glows, grid patterns, gradient meshes, blur blobs |
    53→    53→| **H. Layout Transition** | Responsive layout changes or animated section transitions | Resize / scroll position | CSS Grid/Flexbox + transitions | Column count changes, sticky headers, collapsing sections |
    54→    54→
    55→    55→### 3.2 Template Analysis Procedure
    56→    56→
    57→    57→For EVERY template received, the AI MUST:
    58→    58→
    59→    59→1. **List all files** in the template ZIP — identify every component file
    60→    60→2. **Read each component** — identify what visual effect it implements
    61→    61→3. **Classify each effect** using the taxonomy above (A through H)
    62→    62→4. **Extract rendering parameters** — canvas size, particle count, speed, colors, easing, thresholds, etc.
    63→    63→5. **Note placement context** — where in the page layout is each effect positioned (hero background, section accent, footer, global overlay, etc.)
    64→    64→6. **Check for JS scripts** in HTML templates — `<script>` tags may contain effect logic not in components
    65→    65→7. **Verify CSS animations** — check `@keyframes`, `transition`, `animation` properties in stylesheets
    66→    66→8. **Create an effects manifest** — a complete list before writing any code
    67→    67→
    68→    68→### 3.3 Universal Canvas Rules (Applies to ALL Category A Effects)
    69→    69→
    70→    70→**DPR Handling (MANDATORY — never skip):**
    71→    71→```js
    72→    72→const resize = () => {
    73→    73→  const dpr = window.devicePixelRatio || 1;
    74→    74→  const rect = canvas.getBoundingClientRect();
    75→    75→  canvas.width = rect.width * dpr;
    76→    76→  canvas.height = rect.height * dpr;
    77→    77→  ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
    78→    78→  // NEVER use ctx.scale(dpr, dpr) — it accumulates on every resize call!
    79→    79→};
    80→    80→resize();
    81→    81→window.addEventListener('resize', resize);
    82→    82→```
    83→    83→
    84→    84→**Cleanup (MANDATORY):**
    85→    85→```js
    86→    86→return () => {
    87→    87→  cancelAnimationFrame(frameRef.current);
    88→    88→  window.removeEventListener('resize', resize);
    89→    89→  // Also disconnect any ResizeObserver if used
    90→    90→};
    91→    91→```
    92→    92→
    93→    93→**Performance:**
    94→    94→- Use `requestAnimationFrame` — never `setInterval` for rendering
    95→    95→- Pre-calculate values outside the render loop where possible
    96→    96→- Pre-assign particle properties (color, size, speed) at creation time — do NOT randomize per frame
    97→    97→- For connecting-line effects, limit distance checks (spatial hashing or simple distance cutoff)
    98→    98→- Use `passive: true` on scroll listeners
    99→    99→
   100→   100→**Placement patterns for canvas effects:**
   101→   101→
   102→   102→| Placement | Position CSS | Canvas sizing | z-index behavior |
   103→   103→|---|---|---|---|
   104→   104→| **Full-viewport overlay** | `fixed inset-0` | `window.innerWidth × innerHeight` | Low z (below content), pointer-events-none |
   105→   105→| **Section background** | `absolute inset-0` within section | Section's bounding rect | Behind section content (z-0 or z-1 within section) |
   106→   106→| **Decorative accent** | `absolute` with explicit size/position | Container's bounding rect | Often with reduced opacity (0.2-0.4) |
   107→   107→| **Inline element** | `relative` within content flow | Parent container size | Same z-level as surrounding content |
   108→   108→
   109→   109→### 3.4 Universal Scroll Reveal Rules (Applies to ALL Category B Effects)
   110→   110→
   111→   111→**An IntersectionObserver client component is ALWAYS required.** Without it, any element starting at `opacity: 0` will remain invisible forever.
   112→   112→
   113→   113→```tsx
   114→   114→// scroll-reveal.tsx — render ONCE in the page
   115→   115→"use client";
   116→   116→import { useEffect } from "react";
   117→   117→
   118→   118→export function ScrollReveal() {
   119→   119→  useEffect(() => {
   120→   120→    const reduceMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
   121→   121→    const els = document.querySelectorAll('.fade-up'); // Adjust selector to match template
   122→   122→
   123→   123→    if (reduceMotion) {
   124→   124→      els.forEach(el => el.classList.add('is-visible'));
   125→   125→      return;
   126→   126→    }
   127→   127→
   128→   128→    const observer = new IntersectionObserver(
   129→   129→      (entries, obs) => {
   130→   130→        entries.forEach(entry => {
   131→   131→          if (entry.isIntersecting) {
   132→   132→            entry.target.classList.add('is-visible');
   133→   133→            obs.unobserve(entry.target);
   134→   134→          }
   135→   135→        });
   136→   136→      },
   137→   137→      { root: null, rootMargin: '0px 0px -8% 0px', threshold: 0.12 }
   138→   138→    );
   139→   139→
   140→   140→    els.forEach(el => observer.observe(el));
   141→   141→    return () => observer.disconnect();
   142→   142→  }, []);
   143→   143→
   144→   144→  return null;
   145→   145→}
   146→   146→```
   147→   147→
   148→   148→**The CSS class names and animation properties must match whatever the template uses.** Common patterns:
   149→   149→
   150→   150→| Template pattern | Hidden state | Visible state | Trigger class |
   151→   151→|---|---|---|---|
   152→   152→| `fade-up` | `opacity: 0; translateY(28px)` | `opacity: 1; translateY(0)` | `.is-visible` |
   153→   153→| `slide-in-left` | `opacity: 0; translateX(-40px)` | `opacity: 1; translateX(0)` | `.is-visible` |
   154→   154→| `scale-in` | `opacity: 0; scale(0.9)` | `opacity: 1; scale(1)` | `.is-visible` |
   155→   155→| `blur-in` | `opacity: 0; filter: blur(10px)` | `opacity: 1; filter: blur(0)` | `.is-visible` |
   156→   156→| `clip-reveal` | `clip-path: inset(0 100% 0 0)` | `clip-path: inset(0 0 0 0)` | `.is-visible` or auto @keyframes |
   157→   157→
   158→   158→**Staggered delays:** If the template staggers child elements (cards in a grid, list items), use `data-delay` attributes:
   159→   159→```css
   160→   160→.reveal-item[data-delay="1"] { transition-delay: 0.08s; }
   161→   161→.reveal-item[data-delay="2"] { transition-delay: 0.16s; }
   162→   162→.reveal-item[data-delay="3"] { transition-delay: 0.24s; }
   163→   163→.reveal-item[data-delay="4"] { transition-delay: 0.32s; }
   164→   164→```
   165→   165→
   166→   166→### 3.5 Universal Parallax Rules (Applies to ALL Category C Effects)
   167→   167→
   168→   168→```tsx
   169→   169→const [scrollY, setScrollY] = useState(0);
   170→   170→useEffect(() => {
   171→   171→  const handleScroll = () => setScrollY(window.scrollY);
   172→   172→  window.addEventListener('scroll', handleScroll, { passive: true });
   173→   173→  return () => window.removeEventListener('scroll', handleScroll);
   174→   174→}, []);
   175→   175→
   176→   176→// Apply via inline style:
   177→   177→style={{ transform: `translateY(${scrollY * speedFactor}px)`, transition: 'transform 0.1s linear' }}
   178→   178→```
   179→   179→
   180→   180→- Speed factor range: `0.1` (subtle) to `0.5` (dramatic)
   181→   181→- Always use `{ passive: true }` on scroll listeners
   182→   182→- Add `will-change: transform` on parallax elements
   183→   183→- Consider `position: sticky` for scroll-linked progress effects
   184→   184→
   185→   185→### 3.6 Universal Staggered Reveal Rules (Applies to ALL Category F Effects)
   186→   186→
   187→   187→Two valid implementation patterns:
   188→   188→
   189→   189→**Pattern A — React state chain (preferred for terminal/sequential content):**
   190→   190→```tsx
   191→   191→const [parentVisible, setParentVisible] = useState(false);
   192→   192→// After parent enters viewport or after a base delay:
   193→   193→effect(() => {
   194→   194→  const timer = setTimeout(() => setParentVisible(true), baseDelay);
   195→   195→  return () => clearTimeout(timer);
   196→   196→}, [trigger]);
   197→   197→
   198→   198→// Each child:
   199→   199→function RevealItem({ visible, delay, children }) {
   200→   200→  const [shown, setShown] = useState(false);
   201→   201→  useEffect(() => {
   202→   202→    if (!visible) return;
   203→   203→    const t = setTimeout(() => setShown(true), delay);
   204→   204→    return () => clearTimeout(t);
   205→   205→  }, [visible, delay]);
   206→   206→  return <div className={`item ${shown ? 'is-shown' : ''}`}>{children}</div>;
   207→   207→}
   208→   208→```
   209→   209→
   210→   210→**Pattern B — CSS animation-delay (preferred for grid items):**
   211→   211→```tsx
   212→   212→{items.map((item, i) => (
   213→   213→  <div key={i} className="reveal-item" style={{ animationDelay: `${i * 100}ms` }}>
   214→   214→    {item.content}
   215→   215→  </div>
   216→   216→))}
   217→   217→```

   221→   221→## 4. Z-Index Layering System
   222→   222→
   223→   223→**Do NOT hardcode a single z-index map.** Instead, follow this **principle-based layering system** and derive the actual values from the template.
   224→   224→
   225→   225→### Layering Principles
   226→   226→
   227→   227→1. **Content is always above decoration** — all interactive/semantic content must be above all background effects
   228→   228→2. **Navigation is always on top** — sticky/fixed nav must be above everything including content
   229→   229→3. **Overlays (modals, toasts) above nav** — if the template has them
   230→   230→4. **Background effects between page bg and content** — atmospheric effects sit in the middle layer
   231→   231→5. **Noise/texture overlays are ambiguous** — they can be above or below content depending on desired effect. Check the template. If they dim content, put them above content with low opacity. If they add texture without dimming, put them above background effects but below content.
   232→   232→
   233→   233→### General Layer Order (bottom to top)
   234→   234→
   235→   235→```
   236→   236→Layer 0:   Page background (solid color or gradient)
   237→   237→Layer 1-N: Background atmosphere effects (gradients, grid patterns, decorative canvas)
   238→   238→Layer M:   Mid-layer effects (floating particles, parallax elements)
   239→   239→Layer X:   All content sections (the main page content)
   240→   240→Layer Y:   Texture overlays (noise, grain) — IF they should dim content
   241→   241→Layer Z:   Navigation (sticky/fixed header)
   242→   242→Layer Z+:  Overlays (modals, toasts, drawers)
   243→   243→```
   244→   244→
   245→   245→### How to Derive Values for a Specific Template
   246→   246→
   247→   247→1. Read the template's CSS/JS — find all `z-index`, `position: fixed`, `position: sticky`, `position: absolute` values
   248→   248→2. Map them to the layer order above
   249→   249→3. Assign numeric values with enough gaps for future insertion (e.g., 0, 1, 5, 10, 50, 100)
   250→   250→4. **Test by asking:** "Can the user click/interact with content?" If not, a decoration layer is covering it.

   254→   254→## 5. Theme System
   255→   255→
   256→   256→**Do NOT hardcode colors or fonts.** Always extract from the source HTML or user spec first.
   257→   257→
   258→   258→### 5.1 Theme Extraction
   259→   259→
   260→   260→1. Read the user's source HTML — find `<style>`, `tailwind.config`, CSS variables, or inline color values
   261→   261→2. Identify: background color, foreground/text color, surface/card color, border color, accent colors (primary + secondary), muted text color
   262→   262→3. Identify: body font family + weights, monospace font family + weights
   263→   263→4. Identify: any border-radius, spacing patterns, shadow styles
   264→   264→
   265→   265→### 5.2 CSS Custom Properties Template
   266→   266→
   267→   267→Register ALL theme values as CSS custom properties. This is the canonical structure — fill in values from extraction:
   268→   268→
   269→   269→```css
   270→   270→:root {
   271→   271→  --background:  <extracted>;
   272→   272→  --foreground:  <extracted>;
   273→   273→  --surface:     <extracted>;   /* Card/panel backgrounds */
   274→   274→  --edge:        <extracted>;   /* Borders, dividers */
   275→   275→  --accent-a:    <extracted>;   /* Primary accent (CTAs, highlights) */
   276→   276→  --accent-b:    <extracted>;   /* Secondary accent (links, info) */
   277→   277→  --muted:       <extracted>;   /* Secondary text */
   278→   278→  --radius:      <extracted>;   /* Default border-radius */
   279→   279→}
   280→   280→```
   281→   281→
   282→   282→### 5.3 Tailwind v4 Theme Registration
   283→   283→
   284→   284→```css
   285→   285→@theme inline {
   286→   286→  --font-sans:  <extracted body font>;
   287→   287→  --font-mono:  <extracted mono font>;
   288→   288→  --color-background: var(--background);
   289→   289→  --color-foreground: var(--foreground);
   290→   290→  --color-surface:    var(--surface);
   291→   291→  --color-edge:       var(--edge);
   292→   292→  --color-accent-a:   var(--accent-a);
   293→   293→  --color-accent-b:   var(--accent-b);
   294→   294→  --color-muted:      var(--muted);
   295→   295→  --radius-sm: calc(var(--radius) - 4px);
   296→   296→  --radius-md: calc(var(--radius) - 2px);
   297→   297→  --radius-lg: var(--radius);
   298→   298→  --radius-xl: calc(var(--radius) + 4px);
   299→   299→}

   322→   322→## 6. Layout Architecture
   323→   323→
   324→   324→**Do NOT assume a fixed layout structure.** Extract the layout from the template and source HTML.
   325→   325→
   326→   326→### 6.1 Layout Extraction Procedure
   327→   327→
   328→   328→1. **Identify sections** — scan the template for distinct page sections (hero, about, services, features, pricing, testimonials, contact, footer, etc.)
   329→   329→2. **Map section → component** — each section becomes a separate component file
   330→   330→3. **Extract grid/flex layout** — note column counts, breakpoints, gaps, max-widths
   331→   331→4. **Note the max-width pattern** — most templates use a consistent content max-width. Extract it and register as `--max-content` or `max-w-content` in Tailwind.
   332→   332→5. **Check hero vs content width consistency** — if the hero uses a different width than content sections, note whether this is intentional (design choice) or a mismatch (bug). Ask the user if unclear.
   333→   333→
   334→   334→### 6.2 Universal Layout Rules
   335→   335→
   336→   336→- **Consistent max-width:** All sections SHOULD use the same content max-width unless the template deliberately varies it
   337→   337→- **Consistent horizontal padding:** All sections use the same `px-4 sm:px-6` (or whatever the template specifies)
   338→   338→- **Section dividers:** Use consistent border or spacing between sections
   339→   339→- **Effect placement:** Canvas/decorative effects are typically `absolute` or `fixed` within/behind sections, never in the content flow
   340→   340→
   341→   341→### 6.3 Page Shell Structure
   342→   342→
   343→   343→```
   344→   344→<main> (relative, min-h-screen, overflow-x-hidden)
   345→   345→├── <ScrollReveal />         ← IntersectionObserver (if any Category B effects exist)
   346→   346→├── <GlobalCanvasFX />      ← If any full-viewport canvas effects exist (Category A, fixed)
   347→   347→└── <div content-layer>     ← All content sections
   348→   348→    ├── <Navigation />
   349→   349→    ├── <Section1 />
   350→   350→    ├── <Section2 />
   351→   351→    ├── ...
   352→   352→    └── <Footer />
   353→   353→```
   354→   354→
   355→   355→Only include `<ScrollReveal />` and `<GlobalCanvasFX />` if the template actually has those effect types. Do NOT include them unconditionally.

   359→   359→## 7. CSS Utility Classes
   360→   360→
   361→   361→**Do NOT hardcode a fixed list.** Extract utility classes from the template's CSS.
   362→   362→
   363→   363→### 7.1 Extraction Procedure
   364→   364→
   365→   365→1. Read ALL CSS in the template (stylesheets, `<style>` tags, Tailwind config)
   366→   366→2. Identify every custom class that defines a visual state (animation, hover, transition, pseudo-element)
   367→   367→3. Categorize each:
   368→   368→   - **Animation classes:** Define `@keyframes` or `transition` for motion
   369→   369→   - **State classes:** Define hover/focus/active appearances
   370→   370→   - **Layout classes:** Define structural patterns (glass, terminal, card)
   371→   371→   - **Pseudo-element classes:** Use `::before` or `::after` for decorative content (noise, cursors, glows)
   372→   372→4. Port ALL of them to `globals.css` under `@layer utilities`
   373→   373→
   374→   374→### 7.2 Universal CSS Rules
   375→   375→
   376→   376→- All animations MUST have `@media (prefers-reduced-motion: reduce)` overrides
   377→   377→- All interactive elements MUST have `:focus-visible` styles
   378→   378→- Canvas containers MUST have `pointer-events-none` unless they accept input
   379→   379→- `will-change` should be added to elements with frequent transform/opacity animations
   380→   380→- Use `cubic-bezier(0.22, 1, 0.36, 1)` for smooth deceleration (or match the template's easing)

   384→   384→## 8. Common Pitfalls (Template-Agnostic)
   385→   385→
   386→   386→These are structural pitfalls that apply regardless of template:
   387→   387→
   388→   388→| # | Pitfall | Symptom | Fix |
   389→   389→|---|---|---|---|
   390→   390→| 1 | **IntersectionObserver missing** | All scroll-reveal elements stay invisible | Create a `scroll-reveal.tsx` client component that observes all reveal selectors |
   391→   391→| 2 | **`ctx.scale()` in resize handler** | Canvas rendering breaks/glitches on window resize | Use `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)` — `scale()` accumulates |
   392→   392→| 3 | **Randomizing properties per frame** | Particles/effects flicker randomly | Pre-assign all stable properties (color, size, speed) at object creation |
   393→   393→| 4 | **Z-index layer conflict** | Effects invisible or blocking content | Follow Section 4 layering principles; test interactivity |
   394→   394→| 5 | **Canvas sized to scrollHeight** | Full-page canvas effects invisible | Use `window.innerHeight` for fixed canvases |
   395→   395→| 6 | **Inconsistent max-width** | Jarring width changes between sections | Use same `max-w-content` unless template deliberately differs |
   396→   396→| 7 | **Tailwind v4 `@apply` with custom vars** | Build error | Use direct CSS property assignment in `@layer base` instead |
   397→   397→| 8 | **`next/font` variable not on body** | Fonts don't apply | Apply font variable class string to `<body>` in layout.tsx |
   398→   398→| 9 | **Missing cleanup in useEffect** | Memory leaks, orphaned animations, duplicate listeners | Always return cleanup: `cancelAnimationFrame`, `removeEventListener`, `observer.disconnect` |
   399→   399→| 10 | **Forgetting `"use client"`** | Server component error for canvas/interactive components | All components using hooks (`useState`, `useEffect`, `useRef`) must have `"use client"` |
   400→   400→| 11 | **Effect container too small** | Effect looks tiny, not atmospheric | Check template's original container size — decorative effects often use 600-800px+ containers, not small grid columns |
   401→   401→| 12 | **CSS animation without reduced-motion fallback** | Animation still runs when user prefers no motion | Always add `@media (prefers-reduced-motion: reduce)` that sets `animation: none; opacity: 1; transform: none` |

   477→   477→## 12. Workflow Instructions for AI
   478→   478→
   479→   479→### Phase 1 — Analyze
   480→   480→1. Read ALL input materials (template ZIP, source HTML, theme spec, screenshots)
   481→   481→2. **Extract content** from source — all text, links, sections, data, images, contact info
   482→   482→3. **Extract theme** — colors, fonts, spacing, design tokens, CSS variables
   483→   483→4. **Audit template effects** — using Section 3.2 procedure, classify EVERY visual effect
   484→   484→5. **Extract layout** — section structure, grid columns, max-widths, responsive breakpoints
   485→   485→6. **Create effects manifest** — complete numbered list of all effects with their category, parameters, and placement
   486→   486→
   487→   487→### Phase 2 — Plan
   488→   488→1. Map source content → Next.js section components
   489→   489→2. Map template effects → implementation approach (which category, which canvas pattern)
   490→   490→3. Identify z-index layering for this specific template
   491→   491→4. Plan creative enhancements (if user wants AI to go beyond template)
   492→   492→5. Create file-by-file implementation plan
   493→   493→6. **Present the plan to the user before building** if anything is ambiguous
   494→   494→
   495→   495→### Phase 3 — Build
   496→   496→1. Setup Next.js project with correct `next.config.mjs`
   497→   497→2. Configure `globals.css` — theme vars (from extraction) + ALL utility/animation classes (from template)
   498→   498→3. Setup `layout.tsx` with correct fonts and metadata
   499→   499→4. Build global effect components (scroll-reveal, global canvas effects)
   500→   500→5. Build all section components with their content and local effects
   501→   501→6. Assemble in `page.tsx` with correct z-index layering
   502→   502→7. **Verify ALL of these before declaring done:**
   503→   503→   - `npm run build` succeeds
   504→   504→   - All canvas effects use `setTransform()` not `scale()`
   505→   505→   - IntersectionObserver exists if any scroll-reveal effects are present
   506→   506→   - Z-index layering is correct (content above effects, nav on top)
   507→   507→   - All animations have `prefers-reduced-motion` fallback
   508→   508→   - Content matches source exactly (no text alterations)
   509→   509→
   510→   510→### Phase 4 — Revise
   511→   511→1. Read user feedback + any new screenshots
   512→   512→2. Identify minimum set of files to change
   513→   513→3. Edit only what's needed
   514→   514→4. Output changed files as ZIP with folder path structure
   515→   515→5. Confirm what changed and why

   522→   522→

   525→   525→- **Hover states:** Add glow effects, subtle transforms, color shifts, border animations

   527→   527→- **Transitions between sections:** Gradient dividers, animated SVG separators, morphing shapes

   531→   531→- The user's content and messaging — do NOT alter text

   534→   534→- Accessibility — `prefers-reduced-motion`, aria labels, focus states, semantic HTML
